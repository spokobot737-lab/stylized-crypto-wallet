# Frame Wallet 0.8.0

Zmiana w istniejącej aplikacji Electron/React/TypeScript. Nie wymaga obowiązkowego serwera developera, nowego seeda, klucza czatu ani konta punktowego. PIN, urządzeniowa ochrona sejfu i potwierdzenia systemowe pozostają. Gry są dostępne również po lokalnym odblokowaniu bez połączenia. Nie wykonano żadnej transakcji mainnet.

## Uruchomienie i kontrola

Node 24: `npm ci`, `npm run dev`. Windows x64: `npm run dist:win`; instalator w `release/FRAME-Wallet-0.8.0-Setup-x64.exe`. Gotowy EXE jest zasobem GitHub Releases, nie zawartością automatycznego ZIP-u źródeł.

Kontrole: `npm test`, `npm run build`, `node scripts/ui-games-080.mjs`, `node scripts/ui-profile-080.mjs`, `node scripts/ui-smoke-060.mjs`, `node scripts/ui-frame-run.mjs`, `node scripts/ui-frame-run-wallet.mjs`. `node --import tsx scripts/smoke.mjs` wykonuje istniejący pełny test Windows. Lokalny Linux nie udostępnia używanego przez właściwy start gniazda pojedynczej instancji ani keyringu; test realnego mostu używa jawnie testowej osłony w `tests/support/`, bez zmiany zabezpieczeń produkcyjnych. Fikstury nie trafiają do instalatora.

## NFT z pliku

W NFT → Utwórz wybierz lub przeciągnij plik, nazwę (domyślnie nazwa pliku), opcjonalny opis, sieć i metodę zapisu. Potwierdź publiczną dostępność. Formularz nie wymaga ręcznego URI. Kolekcje, serie i ręczny adres pozostają w Zaawansowanych.

Wspólny adapter rozpoznaje format po bajtach (nie ufa rozszerzeniu), zachowuje oryginał, wylicza SHA-256 i dodaje `properties.frame_original` v1: algorytm, hash, rozmiar, MIME i nazwę. Nie uruchamia zawartości. PNG/JPEG/WebP mają podgląd, inne pliki nazwę i rozmiar. W szczegółach NFT przycisk **Sprawdź hash oryginalnego pliku** pobiera ograniczone dane bez wykonywania i porównuje SHA-256.

- Ethereum/Robinhood: pliki dowolnego formatu do **8192 bajtów** mogą zostać zawarte w publicznym data URI. Kontrakt `FrameEmbeddedCollection` oparty na istniejącym OpenZeppelin ERC721URIStorage zapisuje URI do 24 000 znaków, nie ma metody zmiany URI. Pierwszy mint tworzy jeden token #1 do nadawcy. Wysoka opłata może uruchomić istniejący limit bezpieczeństwa, wtedy nic nie jest podpisywane. Nie jest to darmowy zapis blockchainowy.
- Pliki do **5 MB**, obrazy/PDF/tekst: istniejący adapter Pinata v3, własny token w Integracjach chroniony systemowo. Zapisuje oryginał, potem standardowy JSON. Pinowanie utrzymuje **konto użytkownika Pinata**, a nie węzeł FRAME. Darmowy plan ma limity; usunięcie pinu/wygaśnięcie usługi może pozbawić plik dostępności. Binaria ZIP/octet-stream są blokowane w tym adapterze, bo zasady Pinata nie gwarantują ich publicznego hostingu. Do takich małych plików służy data URI, do większych własny publiczny URI w Zaawansowanych.
- Solana Core: limit URI 200 znaków i limit rozmiaru transakcji wymagają krótkiego adresu IPFS/HTTPS. Bez konta zapisu nie da się bezpiecznie i uczciwie opublikować dowolnego dużego pliku. Nie zastępujemy go ścieżką lokalną ani blob URL. Uprawniony właściciel aktualizacji Core może zmienić metadane; interfejs o tym informuje.

Dziennik przygotowania i gotowy podpis są szyfrowane przez istniejący magazyn. Powrót po restarcie pozwala wznowić zapisane metadane lub rozgłosić **dokładnie tę samą podpisaną transakcję**, bez nowego mintu. Gdy przerwa nastąpi dokładnie między oznaczeniem rozpoczęcia podpisu a zapisem gotowego podpisu, aplikacja zatrzymuje automatyczne ponowienie i wymaga sprawdzenia historii. Wygasłego podpisu Solana nie zastępuje nowym mintem. To zachowawcze ograniczenie, nie obietnica bezbłędnego odzyskania w każdej awarii dysku.

Token nie zapobiega kopiowaniu pliku ani mintowaniu podobnego tokena przez inne osoby. Tożsamość NFT obejmuje sieć, środowisko, kontrakt/mint i token ID. Lokalne minty są weryfikowane pod kątem własności i mogą być widoczne bez pełnego indeksu. Pełne listy Ethereum/Solana nadal zależą od Alchemy/Helius.

## Robinhood Chain

Dokumentacja sprawdzona 2026-11-06: https://docs.robinhood.com/chain/connecting/

| Środowisko | chain ID | RPC | Eksplorator |
|---|---:|---|---|
| Mainnet | 4663 | https://rpc.mainnet.chain.robinhood.com | https://robinhoodchain.blockscout.com |
| Testnet | 46630 | https://rpc.testnet.chain.robinhood.com | https://explorer.testnet.chain.robinhood.com |

Waluta gazu: ETH. Faucet testnet: https://faucet.testnet.chain.robinhood.com. Publiczne RPC są według dokumentacji limitowane i niezalecane do zastosowań produkcyjnych. Próby rzeczywistych POST `eth_chainId` dla **obu** adresów w tym środowisku zwróciły **HTTP 403**, nie wynik chain ID. Nie przedstawiamy samych wartości dokumentacji jako pozytywnego testu RPC.

Wspólne funkcje EVM sprawdzają rzeczywisty chain ID przed saldem, wyceną, ponowną walidacją i rozgłoszeniem. Nie ma cichego przełączenia na Ethereum. Na pulpicie panel Robinhood oferuje odczyt, QR/odbiór, wysyłkę ETH, ręczny import kontraktów ERC-20 i NFT oraz historię Blockscout z paginacją. Symbol tokena nie stanowi potwierdzenia emitenta. Nie wpisano fikcyjnych tokenów USDC ani kontraktów mintowania Robinhood.

Nie potwierdzono darmowej dostępności indeksu Blockscout ani transferów na publicznym testnecie. Awaria jest komunikatem, nie pustą kompletną historią. Lista NFT Robinhood obejmuje ręcznie zaimportowane i lokalnie utworzone aktywa; brak globalnego indeksu. Cache i pliki importów rozdzielają portfel oraz środowisko. Nie integrujemy rachunków maklerskich, akcji ani mostów.

Kontrakty kompiluje `npm run build:contract`; kod, ABI, bytecode, wersja kompilatora i referencje immutable są w `contracts/` oraz `electron/assets/generated/`. Nowy kontrakt tworzy dopiero jawnie potwierdzona operacja użytkownika w wybranej sieci. Nie ma predefiniowanego adresu wdrożenia ani automatycznego wdrażania mainnet. Testy używają lokalnego Ganache z ID 46630. Rzeczywiste wdrożenie testnet i weryfikacja kodu w eksploratorze pozostają do wykonania, gdy RPC i testowe ETH będą dostępne.

## Przelewy w rozmowach

Chat → otwórz zweryfikowany kontakt → **+**. ETH/USDC/NFT na Ethereum i ETH/importowane ERC-20/NFT na Robinhood przechodzą przez istniejący pipeline portfela. To nie nowy signer. Brak zweryfikowanego adresu Solana/Bitcoin w obecnym wiązaniu wyłącza te rodziny dla tego przepływu. Sieć jest wybierana jawnie, nie wnioskowana z `0x`.

Dane kontaktu, aktywny portfel, środowisko, saldo, nonce, opłata i własność są kontrolowane przed podpisem. Następnie występuje systemowe potwierdzenie. Widoczne są nadawca, odbiorca, kwota, sieć i maksymalna opłata. Nie ma automatycznej autoryzacji na podstawie wiadomości.

Karty są wersjonowanym komunikatem wewnątrz NIP-17. Otrzymany hash nie jest dowodem zapłaty. **Sprawdź w sieci** kontroluje paragon, status, kanoniczny blok, nadawcę, odbiorcę, wartość/kontrakt/token ID i zdarzenia Transfer/TransferSingle/TransferBatch. Wykrywa stany pending, unknown, failed, rejected i reorganized. Zastąpionej transakcji bez dostępnego indeksu nonce nie odróżnia pewnie od nieznanej; wyjaśnia to zamiast oznaczać zapłatę jako potwierdzoną.

Oddzielny zaszyfrowany dziennik kart i deduplikacja po hash/rozmowa zapewniają, że po problemie publikacji przycisk **Ponów tylko publikację karty** nie wywołuje płatności. Udane wysłanie do lokalnej kolejki nie obiecuje retencji ani doręczenia relaya. Przed kolejnym przelewem przy niepewnym wyniku sprawdź zapisany hash.

Test na dwóch kontach: utwórz/importuj dwa portfele testowe, aktywuj Chat, wymień jedno zaproszenie i zaakceptuj prośbę. Ustaw Testnet w obu aplikacjach. Wybierz tę samą sieć i porównaj pełny adres odbiorcy. Po wysyłce sprawdź kartę na drugim koncie. Do próby awarii odłącz relaye po potwierdzeniu w RPC; ponawiaj tylko kartę. Automatyczne testy wykonują ten przepływ podpisów/odbiorcy/kart na lokalnym EVM i kontrolowanym transporcie, nie na finansowanych publicznych sieciach.

## Profile i forum

Profil: **Chat → Więcej → Edytuj profil publiczny** albo **Społeczność → Mój profil publiczny**. Nick publiczny jest niezależny od lokalnej nazwy. Szkic jest szyfrowany w istniejącej historii czatu i nie wysyła zdarzeń. Wybór awatara NFT w edytorze sprawdza własność, w tym dodatnie ERC-1155, i zapisuje tylko szkic. Publikacja wymaga osobnej zgody. Banery i awatary są małymi, normalizowanymi obrazami bez ścieżek lokalnych. Nie ma odznaki sugerującej bieżącą własność NFT po jego transferze.

Aktualizacja profilu podpisana jest dotychczasowym kluczem czatu powiązanym podpisem portfela. Stare aktualizacje nie nadpisują nowszych; remisy rozstrzyga ID. Kontakty dostają szyfrowaną aktualizację, a dopiero wybrana publikacja wysyła publiczne zdarzenie społeczności. Lokalny alias kontaktu zachowuje pierwszeństwo. Zmiana nazwy portfela po wyborze niezależnego nicku go nie nadpisuje.

HTML do 2500 znaków: DOMPurify, zamknięta lista tagów/atrybutów i wartości CSS. `iframe sandbox=""` bez uprawnień; wewnętrzny CSP zabrania skryptów, połączeń, obrazów, ramek, formularzy i obiektów. Usunięte event handlery, URL-e, formy, SVG, osadzenia, CSS position/z-index/animation/import. Ograniczona wysokość. Iframe ma inny origin i nie otrzymuje preload; IPC akceptuje wyłącznie główną ramkę. Nie dodano `allow-scripts` ani `allow-same-origin`.

Forum to publiczne podpisane zdarzenia Nostr, nie E2EE i nie Frame P2P. Te same znane relaye, bez dodatkowego serwera. Wątki/odpowiedzi, profile, lokalne wyciszanie/blokowanie i oznaczenie zgłoszenia. Zgłoszenie pozostaje lokalne, nie udajemy panelu moderatora. Historia ograniczona do 200 zdarzeń, kolejka do 20. Starsze strony nakładają graniczną sekundę i deduplikują ID; przy bardzo gęstej sekundzie lub brakach relaya nie ma gwarancji pełnej historii.

Publiczny status jest domyślnie wyłączony. Jawny opt-in, podpisany heartbeat co ok. 60 s, ważność najwyżej 120 s. Ukrycie widoku/opuszczenie forum wyłącza heartbeat; nagłe zamknięcie rozwiązuje wygaśnięcie. Lista to ostatnio zaobserwowani, nie wszyscy korzystający z aplikacji ani dowód człowieczeństwa. Nie publikujemy IP/sald. Relaye widzą połączenie sieciowe. Bezpłatna infrastruktura może wymagać autoryzacji, odrzucić dane lub usunąć historię. Nie potwierdzono odbioru publicznych postów między dwoma rzeczywistymi komputerami; test pary używa podpisanych zdarzeń i kontrolowanego transportu.

## Gry

FRAME Run (stały krok 60 Hz, skok i kucanie), Szachy (chess.js, lokalne dwie osoby), Snake, Blackjack, Ruletka jednozero, Pasjans Klondike. Żadnych embedów/CDN, logowania lub pobierania silnika podczas rozgrywki. Wyłącznie zasoby lokalne. Pause na blur, obsługa dotyku/klawiatury, restart, wyciszanie syntetyzowanego dźwięku i reduced-motion. Nie ma animowanej zawartości HTML nad transakcjami.

Klondike: dobieranie jednej karty, dowolne przejścia stosu, legalne kolumny/fundamenty, odkrywanie, zapis układu i cofanie do 100 ruchów bieżącej sesji. Szachy: roszada, en passant, promocja, szach/mat/pat, powtórzenia, 50 ruchów i niewystarczający materiał. Brak online matchmakingu i AI.

Blackjack: talia 52 kart przed rozdaniem, as 1/11, dealer stoi na miękkim 17, blackjack 3:2, wygrana 1:1, remis zwraca stawkę, bez split/double/insurance. Ruletka: 37 wyników, numer 35:1, zewnętrzne 1:1, tuzin 2:1, zero przegrywa zewnętrzne. Losowanie systemowe lokalne bez obietnicy zewnętrznej weryfikowalności. Tylko niewymienialne kredyty, bez krypto, depozytów, wypłat i nagród. Opuszczenie rozpoczętego Blackjacka traci jego wirtualną stawkę; reset odnawia zabawową pulę.

Nowe rekordy i postęp mają wersjonowane lokalne klucze per portfel. Stary rekord `frame:run:best`, ustawienie wyciszenia oraz serwerowa księga v1 nie są kasowane. Nowe zasady runnera mają osobny rekord, stary jest widoczny z opisem. Poprzedni tryb punktowy jest dostępny w rozwijanej sekcji i nadal wymaga opcjonalnego backendu z 0.7.0; nie jest zależnością sześciu gier.

## Migracja i zakres weryfikacji

Historia czatu v2 → v3: zaszyfrowana kopia `.v2.bak` z wyłącznym utworzeniem przed zapisem, zachowanie identyfikatorów, czasów, kluczy, kontaktów i kolejki. v1 nadal przechodzi przez konserwatywną migrację i `.v1.bak`. Nowe wpisy/szkice/publiczny cache nie zmieniają formatu sejfu, PIN-u i adresów. Zachowano ustawienia motywów, ruchu, rozmiarów i widoczności widżetów.

Lokalny przebieg `npm test`: **81/81 zaliczone**. Typecheck i build zaliczone. Testy interfejsu sześciu gier offline, HTML profilu, czatu/NFT oraz rzeczywistego mostu Electron zaliczone.

Testy obejmują stare scenariusze portfela/czatu/NFT/historii oraz reguły sześciu gier, rzeczywisty lokalny mint obrazu i tekstu, odczyt drugim providerem i SHA-256, blokadę duplikatu po restarcie, ponowienie tego samego podpisu, odbiorcę powiązanego podpisem i fałszywe karty, rzeczywiste ERC-20/721 oraz bibliotekę istniejących testów ERC-1155/Solana, publikację profilu/szkic/out-of-order, parę forum, blokowanie i presence, złośliwy HTML/CSS, brak dostępu do parent/native API oraz uruchomienie i podstawowe działania wszystkich sześciu gier z wyłączoną siecią.

Nie potwierdzono rzeczywistej darmowej publikacji Pinata z nowym kontem i odczytu na fizycznym drugim urządzeniu, publicznych transakcji Robinhood, produkcyjnej dostępności Blockscout, trwałości relayów ani pełnej ręcznej instalacji NSIS. Nie zastępujemy tych testów danymi demonstracyjnymi w produkcji. Lokalne testy dotyku i szerokości 420 px nie zastępują testu fizycznego telefonu.

Źródła wymagań usług: https://docs.pinata.cloud/account-management/limits, https://github.com/cure53/DOMPurify, https://github.com/jhlywa/chess.js. Darmowy limit Pinata API opisany obecnie jako 60 zapytań/min; ograniczenia binariów wymagają indywidualnej zgody usługi. Projekt nie zawiera jej sekretów ani własnego publicznego hostingu.

Dodatkowy odczytowy test połączenia do `wss://nos.lol` i `wss://auth.nostr1.com` w środowisku implementacji zakończył się `getaddrinfo EAI_AGAIN`. Nie opublikowano przy tym żadnej tożsamości ani wpisu. To brak lokalnego potwierdzenia infrastruktury, nie dowód globalnej awarii usług. Nowe rozszerzone profile i karty przelewów wymagają zgodnych klientów Frame 0.8 po obu stronach; starsze klienty mogą je odrzucać.

Rozszerzony test interfejsu sprawdza też realny zapis prywatnego szkicu bez publikacji, izolowany podgląd profilu, układ forum z podpisanym wątkiem/odpowiedzią i presence na kontrolowanym relayu oraz wybór pliku i domyślną nazwę w uproszczonym formularzu NFT.
